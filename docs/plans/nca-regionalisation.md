# Plan: NCA regionalisation

> **Status:** Done

Spec: [docs/specs/nca-regionalisation/spec.md](../specs/nca-regionalisation/spec.md)

## Overview

Build the seven stages as one Python package, `src/nca/`, one module per stage.
Stages never hand objects to each other: each saves CSV, GeoJSON and JSON that
a reviewer can open without this code, and the next one reads those files back.
That is what lets any stage rerun alone, and what lets the determinism test
compare two runs file by file.

Every input comes through one reader, `src/nca/inputs.py`. That single door is
what makes the demand firewall and the sealed window enforceable rather than a
matter of trust: the reader is built for one named stage, and refuses demand to
any stage but evaluate.

The fixture set is generated by real code (`src/nca/fixture.py`) from sums of
sine waves, never a random generator, and a test regenerates it and compares it
with the committed files. So the "known answer" is a planted answer whose
formulas are readable, and the fixture cannot drift from them unnoticed.

## Library choices

The spec named candidates to weigh. What the build uses, and why:

| Job | Chosen | Instead of | Why |
| --- | --- | --- | --- |
| Constrained Ward tree | `sklearn.cluster.ward_tree` with a connectivity matrix | spopt `WardSpatial` | Returns the full merge order and heights, which the cut needs. `WardSpatial` returns labels at one k, so it cannot be cut by merge order |
| Unconstrained Ward | `scipy.cluster.hierarchy.linkage` | | The diagnostic run of R7 |
| Voronoi cells | `shapely.ops.voronoi_diagram` | libpysal | Already a dependency through geopandas; cells are matched to points by location, so the library's output order never matters |
| Neighbour graph | Shapely intersections plus the shared-edge rule | libpysal `Queen`/`Rook` | The rule is "a shared edge of at least 1 metre", which libpysal's weights do not express; writing it out makes it testable |
| Random contiguous partitions | `evaluate.random_contiguous_partition` | spopt `RandomRegions` | Twenty lines, seeded by `numpy.random.default_rng`, so the benchmark is reproducible from the seed the run records |
| Coordinates | pyproj, through geopandas `to_crs` | | Points arrive in WGS 84; every length is metres in British National Grid |

HiClimR, in R, stays a cross-check for a human to run, not a dependency: it
would add an R toolchain to a Python repo for one comparison.

## Decisions taken while building

Three choices the spec left to the plan. Each is visible in the code and
carries a test.

1. **The features stage reads the graph stage's output.** The spec's flow has
   weather going straight into features. It cannot: the national mean must
   cover the points the graph kept, not the offshore ones it dropped, and the
   cell-area weighted option needs cell areas. The system diagram draws this as
   a dotted edge and says so. No weather values cross it.
2. **The disconnected-parts setting takes `stop`, `join_nearest` or
   `fixed_regions`.** The spec's "join with manual links" is what a person
   does, not what code does, so the automatic form is named for what it
   actually does: join the closest pair across the parts, and record it.
3. **Demand arrives already day-adjusted.** The day adjustment is out of scope,
   and the spec's input list asks for a day-adjusted extract, so the evaluate
   stage reads the series as given rather than adjusting it.

nca run all --settings tests/fixtures/nca-regionalisation/settings.toml --out runs/first

# A real run with nothing filled in stops and lists what is missing
printf 'data_source = "real"\n' > /tmp/real.toml
